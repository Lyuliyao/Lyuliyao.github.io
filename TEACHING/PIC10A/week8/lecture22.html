Part A

Designing a Class End to End

Design Goal (Example 15.9.4)

Build a Rational class for fractions n/d. The class invariant: den is strictly positive, and num, den share no common factor — so every fraction is stored in simplified form.

Step 1: Design Decisions

Data members num, den Two ints, both private.
const? readers are const print, equals, arithmetic — none modify state.
Invariant simplified, den > 0 Helpers make_den_positive / simplify enforce it.

Step 2: The Interface

            
class Rational {
public:
    Rational()                   : num(0), den(1) {}
    Rational(int n)              : num(n), den(1) {}
    Rational(int n, int d) : num(n), den(d) {
        assert(den != 0);
        make_den_positive();
        simplify();
    }

    void print() const { cout << num << '/' << den; }
    bool equals(const Rational& other) const {
        return num == other.num && den == other.den;
    }
    bool is_zero() const { return num == 0; }

    Rational      plus(const Rational& other) const;
    Rational     minus(const Rational& other) const;
    Rational     times(const Rational& other) const;
    Rational divided_by(const Rational& other) const;

private:
    int num;
    int den;

    void make_den_positive();
    void simplify();
};
  • Three constructors: 0/1, n/1, n/d.
  • Every reader is const; arithmetic returns a new Rational.
  • make_den_positive and simplify are private helpers.

Step 3: Private Helpers Enforce the Invariant

            
void Rational::make_den_positive() {
    if (den < 0) { num *= -1; den *= -1; }
}

void Rational::simplify() {
    int a = abs(num), b = abs(den);
    while (b != 0) {                  // Euclidean algorithm
        int r = a % b;
        a = b;
        b = r;
    }
    num /= a; den /= a;
}
  • The constructor calls these once on creation.
  • A user never sees them — they live in private.
  • So every Rational in existence is already simplified.

Step 4: Arithmetic Members

            
Rational Rational::plus(const Rational& other) const {
    return Rational(num * other.den + other.num * den,
                    den * other.den);
}
Rational Rational::minus(const Rational& other) const {
    return Rational(num * other.den - other.num * den,
                    den * other.den);
}
Rational Rational::times(const Rational& other) const {
    return Rational(num * other.num, den * other.den);
}
Rational Rational::divided_by(const Rational& other) const {
    assert(!other.is_zero());
    return Rational(num * other.den, den * other.num);
}
  • Each builds a new Rational from the formula.
  • The (int, int) constructor simplifies the result.
  • All four are const — they never modify the caller.

Step 5: Putting It to Work

            
int main() {
    // 2 + (3/4) / (1/5)
    Rational(2).plus(
        Rational(3, 4).divided_by(Rational(1, 5))
    ).print();
    cout << endl;                            // 23/4

    // (2 + 3/4) / (1/5)
    Rational(2).plus(Rational(3, 4))
               .divided_by(Rational(1, 5))
               .print();
    cout << endl;                            // 55/4
}
  • Calls chain: each operation returns a Rational to act on.
  • Output: 23/4 then 55/4.
  • (PIC 10B: overload +, /, << to write r1 + r2/r3.)

Why num and den Are private

If a user could write r.num += 7, the stored fraction would no longer be simplified, and equals (which compares numerators and denominators directly) would return wrong answers. Encapsulation is what keeps the invariant trustworthy.
Part B

Default Arguments

One function, two ways to call it — with or without trailing arguments.

What a Default Argument Is

A default argument supplies a value the caller may omit. One function then serves the common case and the customized case — Chapter 16.

Default Argument Syntax

            
void greet(std::string name, std::string punct = "!") {
    std::cout << "Hello, " << name << punct << "\n";
}

greet("Ada");          // Hello, Ada!
greet("Ada", ".");     // Hello, Ada.
greet("Ada", "?");     // Hello, Ada?
  • = "!" is the default for punct.
  • Omitting it uses the default.
  • Supplying it overrides the default.

Defaults Go in the Declaration

            
// log.hpp
void log(std::string msg, int level = 1);   // default HERE

// log.cpp
#include "log.hpp"
void log(std::string msg, int level) {      // NO default here
    std::cout << "[" << level << "] " << msg << "\n";
}
  • The default lives where callers see it — the header.
  • Repeating it in the definition is an error.
  • If there is no header, put it on the single declaration.

The Trailing-Parameter Rule

            
void box(int w, int h = 1, int d = 1);   // OK
void bad(int w = 1, int h);              // error: h has no default
  • Once a parameter has a default, all after it must too.
  • Defaults are filled from the right end leftward.
  • bad could never omit w while passing h.

Omitting Only Trailing Arguments

            
void box(int w, int h = 1, int d = 1);

box(5);          // w=5, h=1, d=1
box(5, 2);       // w=5, h=2, d=1
box(5, 2, 3);    // w=5, h=2, d=3
box(5, , 3);     // ERROR: cannot skip the middle one
  • You may only drop arguments from the right.
  • There is no syntax to skip a middle argument.
  • To set d you must also pass h.

The Ambiguity Trap

            
void f(int a);                 // candidate A
void f(int a, int b = 0);      // candidate B

f(3, 4);   // calls B, fine
f(3);      // AMBIGUOUS: A matches, B matches via default
  • f(3) fits f(int) exactly.
  • It also fits f(int, int=0) with the default.
  • Two equally good matches ⇒ build error.

Example: Different Types Are Fine

            
void print(int x);                       // A
void print(double x, int prec = 2);      // B

print(3);        // A: int matches exactly
print(3.14);     // B: double matches exactly, prec=2
print(3.14, 4);  // B: prec=4
  • The overloads differ in the first parameter's type.
  • Overload resolution decides before defaults come into play.
  • No ambiguity — each call has one best match.

Lecture 22 Summary

Main ideas

  • Design: pick data members, then the operations they need.
  • State the invariant; defend it in the constructor and private helpers.
  • Defaults go in the declaration only.
  • Every parameter after a defaulted one must be defaulted.

Programming habits

  • Make every reader const so const instances stay usable.
  • Prefer one defaulted function over near-duplicate overloads.
  • Do not mix an overload with a default that covers it.

Lecture 22 Review Questions

Classes review

  • Q1. Why make num and den private?
  • Answer: So callers cannot break the simplified-form invariant.
  • Q2. Why is equals marked const?
  • Answer: It only reads members, and a const Rational& must be able to call it.
  • Q3. Why are simplify and make_den_positive private?
  • Answer: They are implementation helpers a user does not need — and should not call — on their own.

Default arguments

  • Q4. Where does a default argument go?
  • Answer: In the declaration (header), not repeated in the definition.
  • Q5. Is void p(int a = 1, int b); legal?
  • Answer: No — all parameters after a defaulted one must be defaulted.
  • Q6. Why is f(3) ambiguous with f(int) and f(int,int=0)?
  • Answer: Both are viable for one argument and neither is strictly better.

Lecture 22 Code Review

Spot the bug

  • Q1. Why does r.equals(s) give a wrong answer here? 
                
// Suppose num/den were public:
Rational r(3, 6);   // stored as 1/2
Rational s(1, 2);   // stored as 1/2

r.num += 7;         // r is now stored as 8/2  (NOT simplified!)
std::cout << r.equals(s);   // ?
  • Answer: equals compares num and den directly, assuming both are simplified. The write to r.num broke that invariant, so r.equals(s) returns false even though 8/2 == 1/2. This is why num and den are private.

Does it compile?

  • Q2. Build result? 
                
void scale(int v);
void scale(int v, double k = 2.0);

int main() { scale(10); }
  • Answer: Build error: scale(10) matches scale(int) exactly and scale(int,double=2.0) via the default — ambiguous.
